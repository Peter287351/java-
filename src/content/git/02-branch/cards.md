## 分支、HEAD 与切换

### 是什么
Git 的分支只是一个指向某个提交的可移动指针，创建分支几乎零成本；`HEAD` 指向当前所在分支（或某个具体提交，即 detached HEAD）。`main` 也是普通分支，并不特殊。

### 怎么用
`git switch -c feat/login` 创建并切换，`git switch main` 切回，`git branch -d feat/login` 删除已合并分支。切换前先 commit 或 stash，避免把未提交改动带过去。

### 常见坑
- 在 detached HEAD 状态直接提交，切走后提交容易变成「悬空」对象，要靠 reflog 找回。
- 分支名与远程跟踪分支混淆：`origin/main` 是远程引用快照，不是本地工作分支。
- 删分支用 `-d` 会拒绝未合并分支，强行删要用 `-D`，先确认真的不要了。

### 面试怎么问
「Git 分支为什么轻？」答它只是 40 字节哈希的指针，不像 SVN 复制整个目录。

## merge 与 rebase

### 是什么
`git merge` 把两条历史汇合成一个新的合并提交，保留原有时间线；`git rebase` 把当前分支的提交「重放」到目标分支顶端，得到线性历史，但会生成新的提交哈希。

### 怎么用
个人本地分支整理提交用 rebase；已经推送到远程、被多人共用的分支不要 rebase，用 merge。冲突时编辑文件 → `git add` → `git rebase --continue` 或 `git commit` 完成合并。

### 常见坑
- `<<<<<<< HEAD`、`=======`、`>>>>>>>` 是冲突标记，必须全部删干净再提交。
- rebase 已推送分支会让同事的本地历史与远程分叉，强推还会覆盖别人工作。
- fast-forward 合并默认不产生合并提交，想保留分支痕迹用 `--no-ff`。

### 面试怎么问
「merge 和 rebase 怎么选？」答是否要保真历史；补一句「公共分支不 rebase」是加分项。

## 动手清单
1. 建两个分支改同一行，合并触发冲突，手动解决后提交；自测标准：能说清三段冲突标记分别代表什么。
2. 对同一个本地分支分别做一次 merge 和一次 rebase，用 `git log --oneline --graph` 对比历史形状。
