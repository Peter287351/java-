## 数据卷与绑定挂载

### 是什么
容器可写层随容器删除消失。命名卷（volume）由 Docker 管理、适合数据库数据；绑定挂载（bind mount）把宿主机目录直接挂进去，适合配置文件与日志。

### 怎么用
`docker run -v /opt/logs:/app/logs app:1.0` 是绑定挂载；`docker volume create dbdata` 后 `-v dbdata:/var/lib/mysql` 是命名卷。Compose 里用 `volumes:` 声明并在服务里引用。

### 常见坑
- 挂载宿主机目录会覆盖容器内该路径原有内容，第一次启动前要确认初始文件。
- 容器内写文件用的是镜像里用户的 UID，宿主机目录权限不匹配会报 Permission denied。
- `docker rm -v` / `docker compose down -v` 会连卷一起删，生产上慎之又慎。

### 面试怎么问
「容器删了数据还在吗？」答只有挂了卷的数据在，且要区分命名卷与绑定挂载的管理方式。

## 网络与容器间通信

### 是什么
默认 bridge 网络里，同一自定义网络的容器可通过服务名/容器名互相解析；端口映射 `-p` 负责把宿主流量送进容器；`--network host` 让容器直接共用宿主网络栈（Linux 有效）。

### 怎么用
Compose 会为项目创建独立网络，服务之间用服务名当主机名，例如 Java 应用的数据库连接写 `jdbc:mysql://mysql:3306/app`，而不是 `127.0.0.1`。

### 常见坑
- 容器里的 `127.0.0.1` 指容器自己，不是宿主机，也不是同网络的其它容器。
- 应用只监听 127.0.0.1 时，即使端口映射了，外部也访问不到，要监听 0.0.0.0。
- 默认的 bridge 网络不支持自动的服务名 DNS，自定义网络才支持。

### 面试怎么问
「Compose 里 app 连 db 为什么写 db:3306？」答同一自定义网络内 Docker DNS 按服务名解析。

## 动手清单
1. 用命名卷起一个数据库容器，写入数据后删除容器再用同一个卷重建，验证数据还在。
2. 在同一自定义网络起两个容器，用服务名互相 ping；自测标准：能解释为什么 127.0.0.1 不行。
