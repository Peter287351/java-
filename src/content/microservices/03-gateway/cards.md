## 网关的路由、断言与过滤器

### 是什么
Spring Cloud Gateway 是统一入口：Route 由 ID、目标 URI、Predicate（什么请求匹配）、Filter（匹配后做什么）组成。常见能力有鉴权、限流、跨域、路径重写、灰度。

### 怎么用
按服务名路由时 URI 写 `lb://order-service`，由网关自己做服务发现与负载均衡。`StripPrefix=1` 去掉第一段路径前缀，让 `/api/orders/1` 转发成 `/orders/1`。

### 常见坑
- 谓词顺序与路径写法不匹配会导致 404，直连后端却正常，这是网关排障第一嫌疑。
- 过滤器里做远程鉴权调用却没设超时，网关线程池会被拖垮。
- 跨域、限流、鉴权都堆在网关，规则越来越多，需要按优先级与作用域管理。

### 面试怎么问
「网关和 Nginx 有什么区别？」答网关在应用层理解服务与路由、可做业务级过滤，Nginx 更偏传输层与静态资源。

## 统一横切能力

### 是什么
全局过滤器（GlobalFilter）对所有路由生效，适合放 traceId、鉴权校验、审计日志；局部过滤器只作用于某条路由。限流常按用户/接口/IP 维度配置。

### 怎么用
鉴权失败直接返回 401，不把请求放到下游；为每个请求生成或透传 traceId，让后续日志能串成一条链路。灰度可按 Header 或元数据把流量导向 v2 实例。

### 常见坑
- 网关已经校验过 Token，下游也不能完全信任，内网仍要做最小校验。
- 限流规则太粗会误伤正常流量，太细则漏掉突发流量。
- 忘记透传 `X-Forwarded-*`，下游拿到的是网关地址而非真实客户端信息。

### 面试怎么问
「怎么做灰度发布？」答网关按 Header/用户标签打标，配合注册中心元数据与负载均衡规则把特定流量导到新版本。

## 动手清单
1. 配一条 `lb://` 路由并加 StripPrefix，用 curl 对比网关路径与后端实际收到的路径。
2. 写一个全局过滤器给请求加 traceId，在网关与下游日志里 grep 同一个值，确认链路串得起来。
