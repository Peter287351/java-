## 流程控制：分支、循环与人工介入

### 是什么
- **条件边**：路由函数按状态返回目标 key → 实现分支。
- **循环**：agent → tools → agent 的环，靠终止条件退出（无工具调用 / 达到最大轮数）。
- **fan-out/fan-in**：一个节点分派多个并行分支，再汇聚合流。
- **interrupt**：在指定节点前暂停，把控制权交给人（审批），人工输入后从断点恢复——checkpoint 持久化状态是恢复的前提。

### 为什么
生产级 Agent 必须有三道闸：**循环上限**（防死循环烧钱）、**人工审批**（高危操作不能自动执行）、**状态持久化**（宕机可恢复）。interrupt + checkpoint 就是 LangGraph 系的答案。

### 怎么用
- 退出条件双保险：模型"不再调用工具" + 硬编码最大迭代次数。
- checkpoint：每个超步后保存状态快照（内存/Redis/DB），恢复时从快照继续。
- 子图（subgraph）：把常用流程封装成节点复用。

### 常见坑
- 只靠模型自己"决定停止"——模型可能无限循环调用工具。
- 审批中断后不保存状态，重启全流程重来。

### 面试怎么问
「Agent 死循环怎么防？」——迭代上限 + 超时 + 每轮成本核算，三闸齐备才敢上线。

## 动手清单

1. 给 ReAct 循环加"最大 5 轮"硬上限，故意让工具永远返回失败观察终止。自测标准：能指出终止发生在哪个条件判断。
2. 用 interrupt 做一个"转账金额 > 1000 需人工审批"流程，中断后注入审批结果恢复。自测标准：能说出恢复时状态从哪来。
