## Agent 实战：从 ReAct 到多 Agent 协作

### 是什么
- **ReAct**：Reasoning + Acting——模型在 agent 节点推理决定"调用哪个工具"，tools 节点执行，观察结果循环往复，直到给出最终答案。
- **多 Agent 编排**：主管模式（supervisor 路由给子 Agent）、流水线模式（顺序交接）、群体协作（swarm）。每个 Agent 可以是独立子图（自带记忆与工具）。
- 生产要素：结构化状态、checkpoint 持久化、traceId 全链路日志、节点幂等、超时与上限。

### 为什么
单 Agent 工具一多选择准确率下降、上下文互相污染：**拆分职责**（每个 Agent 少而精的工具集）+ 图编排路由，是复杂系统的可维护解。

### 怎么用
- 调试：打印/可视化每步状态变化（图结构 + 节点输入输出），先看"路由对不对"再看"模型答对不对"。
- 选型：确定性流程（如审批流）用硬编码图；探索性任务（如研究助手）用 ReAct + 人工节点。

### 常见坑
- 图复杂到没人看得懂 = 反模式：优先简化流程与工具集。
- 子 Agent 的输出没有 schema，主管 Agent 解析靠猜——交接内容要结构化。

### 面试怎么问
「设计一个客服工单 Agent」答：意图路由（条件边）→ 工具子图（查/改单）→ 敏感操作中断审批 → checkpoint 恢复，体现完整工程链路。

## 动手清单

1. 实现"查天气 + 算汇率"双工具 ReAct Agent，记录每轮的消息列表变化。自测标准：能解释模型何时决定停止调用工具。
2. 搭一个主管 Agent 路由两个子 Agent（退款、物流），交接字段结构化。自测标准：能画出完整的图拓扑并指出每条边类型。
