## Tools 与 RAG：让模型"动手"和"查资料"

### 是什么
- **Tools（函数调用）**：`@Tool` 标注方法 + 参数描述 → 框架把工具清单发给模型 → 模型决定调用并回传参数 → 框架执行本地方法 → 结果回填给模型 → 模型生成最终回答。模型不执行代码，只"点菜"。
- **RAG**：文档切分（DocumentSplitter）→ EmbeddingModel 向量化 → 存入 EmbeddingStore（InMemory/Milvus/PGVector…）→ 查询时检索 topK 相关片段 → 拼进 Prompt 生成答案。

### 为什么
模型的知识有截止日期且不知道你的私有数据：工具给它"行动能力"（查订单、发邮件），RAG 给它"私有知识"。两者是 LLM 应用两大地基。

### 怎么用
- 工具描述（@Tool 的 description、@P 参数描述）写得好坏直接决定调用准确率——模型靠描述选工具。
- 检索调参：topK、相似度阈值（score）、必要时重排（rerank）；片段大小与 overlap 影响召回质量。
- 接入 AI Services：`.contentRetriever(...)` 即插即用。

### 常见坑
- 该用工具的场景模型没调用 → 先查工具描述是否含糊、参数是否过多。
- 检索答非所问 → 先看"检索回来的片段对不对"，再怪模型——多数是切分/嵌入/查询改写问题。

### 面试怎么问
「讲一遍 RAG 完整流程」按"切分→嵌入→存储→检索→拼 Prompt→生成"六步答，再补 score 阈值与 rerank 加分。

## 动手清单

1. 写 @Tool 查询天气（mock 数据），观察模型自动选择工具与参数抽取。自测标准：能描述一次工具调用的完整消息往返。
2. 用 InMemoryEmbeddingStore + 内置嵌入模型建 10 条产品 FAQ，问 3 个改述问题验证检索。自测标准：能调 topK/阈值改善一次失败召回。
