# 02 设计模式与工程质量

## 把模式用在该用的地方

### 是什么
常用模式的区分看「要变化的是什么」：
- **策略（Strategy）**：算法/规则有多种，运行时选一种。订单折扣、运费计算、支付渠道路由。
- **模板方法（Template Method）**：流程骨架固定、某几步交给子类。导入导出、审批流程。
- **工厂 / 简单工厂**：把「new 哪个实现」集中到一处，配合 Map 注册可免掉一长串 if-else。
- **装饰器（Decorator）**：不改原类、层层叠加能力。IO 流、带缓存/日志/重试的包装。
- **适配器（Adapter）**：把不兼容的旧接口转成目标接口。接第三方 SDK 时最常见。

Spring 里这些几乎不用手写：`Map<String, Strategy>` 由容器按 bean 名注入，配合 `@ConditionalOnProperty` 或配置中心就能切换实现。

### 为什么
目标是**把变化关进一个笼子**：新增一种折扣规则时只加一个新类，不改下单主流程（对扩展开放、对修改关闭）。判断该不该上模式，看的是「这个地方是否真的在变」，而不是「这本书我读过」。

### 怎么用
- 一开始只有两三个分支，直接 if-else 更清晰；分支开始扩散、且每个分支还在长逻辑时再抽策略。
- 策略实现要无状态，状态放参数里，才能安全地作为单例 bean 共享。
- 给策略一个明确的 key（枚举或字符串），别用 `instanceof` 反推类型再分支，那等于把 if-else 换个地方写。

### 常见坑
- 为了用模式而用模式：一个只有一种实现的「策略接口 + 工厂 + 抽象基类」，徒增三层跳转。
- 在策略实现里改共享成员变量：单例 bean 被并发调用时出现串数据。
- 把模板方法和策略搞混：前者是「流程不变、步骤可变」，后者是「整段算法可替换」。

### 面试怎么问
「项目里怎么用策略模式？」答出场景、如何按 key 路由、Spring 里 Map 注入、以及「不用模式时是什么样、为什么后来要改」，比背 UML 图有说服力。

## 测试与构建：能重复验证才算工程化

### 是什么
测试按成本分层：**单元测试**（不启容器、依赖用 Mockito mock，毫秒级）、**集成测试**（`@SpringBootTest` 会加载完整上下文，秒级到十秒级）、**端到端测试**（跨服务，最慢也最脆）。Maven 的 `test` scope 依赖只在测试编译与运行期可见，不进最终产物；`provided` 表示运行期由容器提供（如 servlet-api）；依赖版本用 `dependencyManagement` 统一声明、子模块不再各写各的版本。

### 为什么
测试金字塔的意义是「便宜的测试多写、昂贵的测试少写」。把本该 mock 掉的逻辑全塞进 `@SpringBootTest`，CI 会越来越慢，最后没人愿意跑。构建工具统一管理依赖，则是为了避免「我本地能跑、线上一启动就 NoSuchMethodError」这类版本漂移。

### 怎么用
- 业务分支逻辑用纯单测覆盖；只有真正需要验证配置装配、事务、SQL 的地方才启 Spring 上下文。
- 测试不许连生产库、不许发真实短信/扣款；用 Testcontainers 或 H2 做可重复的数据环境。
- 依赖冲突先 `mvn dependency:tree -Dincludes=groupId:artifactId` 定位谁引入了旧版本，再用 `dependencyManagement` 或 exclusion 处理。

### 常见坑
- 用 `@MockBean` 把整个上下文 mock 一遍，测完什么真实链路都没覆盖。
- 单元测试依赖执行顺序或当前时间、随机数，CI 上偶发红。
- 把测试工具类打进生产包（scope 写成 compile），徒增包体积与冲突面。

### 面试怎么问
「怎么定位依赖冲突？」答 `dependency:tree` 看引入路径 → `dependencyManagement` 锁定版本 → 用 `mvn -q test` 与启动验证，能顺带提一句 classpath 就近优先，就很扎实。

## 动手清单

### 练习 1：重构一次 if-else
把一段包含三种会员折扣的 if-else 下单逻辑改成 `Map<String, DiscountStrategy>`，新增「学生折扣」时只允许加一个类，不改下单方法。

### 练习 2：看一次依赖树
在一个 Spring Boot 项目里跑 `mvn dependency:tree`，找出传递引入的两个不同版本的同名库，用 dependencyManagement 统一后再跑一遍确认。
**自测标准**：能说清策略与模板方法的区别，能解释为什么多数逻辑不该用 @SpringBootTest 测。
