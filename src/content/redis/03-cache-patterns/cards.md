## 缓存三大问题与一致性

### 是什么
- **穿透**（查不存在的数据，缓存永远未命中直击 DB）：空值缓存 + 参数校验 + 布隆过滤器。
- **击穿**（单个热点 key 过期瞬间，并发打到 DB）：互斥锁重建 / 逻辑过期不删除。
- **雪崩**（大量 key 同时失效或 Redis 宕机）：TTL 加随机抖动、多级缓存、集群高可用、限流降级。

### 为什么
一致性主流方案 **Cache Aside**：读——先缓存后 DB 并回填；写——**先更新 DB，再删除缓存**（而非更新缓存）。删除更稳：避免并发写覆盖与写多读少的无效计算。

### 怎么用
"先更库再删缓存"仍有极小不一致窗口（读线程在删后把旧值写回）：用**延迟双删**或订阅 binlog（canal）异步删除兜底。强一致场景别依赖缓存，直接读库或加锁。

### 常见坑
- 布隆过滤器"可能误判存在、绝不误判不存在"，只能拦截"不存在"的请求。
- 逻辑过期的 value 里要带过期时间字段，读到过期就异步重建并临时返回旧值。

### 面试怎么问
「为什么删缓存而不是更新缓存？」——并发写会乱序覆盖；懒加载天然与读对齐，避免写多读少浪费。

## 动手清单

1. 写代码模拟：线程 A 读缓存→查库（慢）→回填；线程 B 更新库→删缓存。观察 A 回填旧值造成的不一致，再加延迟双删修复。自测标准：能画出不一致的完整时序。
2. 用 Guava/Redis 实现空值缓存（TTL 30s）+ 入参白名单校验，压测不存在的商品 id。自测标准：DB QPS 归零。
