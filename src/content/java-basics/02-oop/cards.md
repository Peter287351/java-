# 02 面向对象

## 封装、继承、多态与重载重写

### 是什么
封装把状态藏进 private、通过方法暴露行为；继承建立「is-a」关系；多态（polymorphism）让父类引用指向子类对象时，被重写的实例方法在运行期绑定到对象的实际类型（动态绑定，dynamic dispatch）。重载（overload）是同一个类里方法名相同、参数列表不同，编译期按参数静态选择；重写（override）是子类以相同签名覆盖父类方法，运行期动态绑定。

### 常见坑
- 方法多态、字段不多态：通过父类引用访问成员变量，看的是编译期类型，没有动态绑定。
- 重写不能缩小访问权限（public 改 private 编译报错），不能抛更宽的受检异常。
- 只有返回值类型不同不构成重载，编译器直接报「方法已定义」。
- static 方法被子类同名方法「覆盖」是隐藏（hiding）不是重写，通过父类引用调用的仍是父类版本。

### 面试怎么问
「重载和重写的区别？」——按「编译期选择 vs 运行期绑定、参数列表不同 vs 签名相同、同类内部 vs 父子类之间」三点对比，再补一句 static 方法只有 hiding 没有多态，一句话拉开差距。

## 初始化顺序、static/final、内部类与 record

### 是什么
创建对象时初始化顺序固定：父类静态块（类加载时执行一次）→ 子类静态块 → 父类实例块 → 父类构造器 → 子类实例块 → 子类构造器。static 成员属于类、全局一份，static 方法没有 this。final 修饰变量只锁「引用不可重新指向」（对象内容仍可改）、修饰方法不可重写、修饰类不可继承。内部类分静态嵌套类（static nested，不持有外部实例）与非静态内部类（inner，隐式绑定外部实例）；匿名内部类捕获的局部变量须 final 或 effectively final。record（JDK 16 转正）是不可变数据载体，自动按组件生成 equals / hashCode / toString。

### 常见坑
- 构造器里调用可被重写的方法：父类构造先于子类字段初始化执行，重写方法会在「半成品对象」上读到 null 或 0。
- final List 里的元素照样能 add——final 锁引用不锁内容。
- 非静态内部类脱离外部实例直接 new Inner() 会编译失败，要 outer.new Inner()。
- record 隐式 final 且已继承 java.lang.Record，不能再 extends 其他类，也没有 setter。

### 面试怎么问
「父类构造器中调用被子类重写的方法会发生什么？」——答出「半成品对象」：父类构造先于子类字段初始化，重写方法拿到默认值产生偶发 NPE；修复思路是把可重写的钩子移出构造器。

## 动手清单

### 练习 1：写出并验证初始化顺序
父子类各含静态块、实例块、构造器，先手写预期输出再运行验证；随后在父类构造器里调用被子类重写的方法，观察子类字段为 null。
自测标准：能完整说出「父静子静、父块父构、子块子构」，并解释构造期 NPE 的成因。

### 练习 2：用 record 重构一个 POJO
把一个只有字段、getter、equals、hashCode、toString 的类改写成 record，对比代码行数。
自测标准：能说出 record 不能继承类、组件不可变、没有 setter、equals 自动按全部组件比较。
