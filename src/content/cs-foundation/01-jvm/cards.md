# 01 JVM 内存与 GC

## 运行时数据区：对象到底存在哪

### 是什么
HotSpot 把内存分成线程共享与线程私有两类。共享的是**堆（Heap）**与**元空间（Metaspace）**：几乎所有对象实例、数组都在堆上分配，类元信息、常量池、方法字节码放在元空间（JDK 8 起用本地内存，不再占用堆）。私有的是**虚拟机栈**（每个方法一个栈帧，存局部变量表、操作数栈）、**本地方法栈**与**程序计数器**。局部变量表里存的是基本类型的值，或指向堆对象的**引用**，不是对象本身。

### 为什么
这样分是让「生命周期短、随方法调用自动创建销毁」的数据走栈，靠出栈即回收，不劳烦 GC；而生命周期跨方法的对象集中放堆，交给 GC 统一判断。元空间改用本地内存，则避免了永久代大小难估、容易 `OutOfMemoryError: PermGen space` 的老问题。

### 怎么用
- 排查内存问题先分清是哪块溢出：堆 → `OutOfMemoryError: Java heap space`；元空间 → `Metaspace`；栈 → `StackOverflowError`（递归过深）；线程过多导致栈总和超限 → `unable to create new native thread`。
- 常用参数：`-Xms` / `-Xmx` 设堆上下限（一般设成相等避免动态扩容抖动）、`-Xss` 设单线程栈大小、`-XX:MaxMetaspaceSize` 限制元空间。

### 常见坑
- 以为「对象在栈上」：栈里只有引用，逃逸分析做的标量替换是 JIT 优化，不能当成语言规则。
- 以为 JDK 8 之后字符串常量池还在永久代：JDK 7 就已把字符串常量池移到堆，JDK 8 连永久代都取消了。
- `-Xmx` 不是进程占用上限：还要算元空间、线程栈、直接内存（NIO/Netty）、JIT 代码缓存，容器里按 `-Xmx` 设 limit 容易被 OOM Kill。

### 面试怎么问
「一个对象 new 出来之后在哪？」——先答堆，补一句栈帧里只有引用，再主动说「逃逸分析可能让 JIT 做标量替换，但那是优化不是规范」，层次就出来了。

## GC：谁该被回收，怎么回收

### 是什么
判断存活用**可达性分析**：从 GC Roots（虚拟机栈中的引用、静态字段、常量、JNI 引用、活跃线程等）出发，能走到的对象存活，走不到的可回收。堆按年代划分，新生代又分 Eden + 两个 Survivor，新对象先进 Eden，熬过一次 Minor GC 就挪到 Survivor 并增加年龄，达到阈值（默认 15）晋升老年代。G1 则把堆切成等大 Region，按回收收益优先选区，配合 `-XX:MaxGCPauseMillis` 控制停顿目标。

### 为什么
**分代假说**：绝大多数对象朝生夕死。把短命对象集中在新生代，用复制算法低成本清理（活对象少，复制便宜）；老年代对象存活率高，用标记-整理/清除更划算。这样避免每次都全堆扫描。

### 怎么用
- 线上先看证据再调参：`jstat -gcutil <pid> 1000` 看各区与 GC 次数耗时，`jmap -dump` 导出堆用 MAT 看支配树，`-XX:+PrintGCDetails`（JDK 9+ 用 `-Xlog:gc*`）留日志。
- 停顿敏感的服务优先 G1 / ZGC，而不是靠调小堆或加大新生代硬扛。

### 常见坑
- 「频繁 Full GC」就盲目调大堆：如果是无界缓存、大对象批量加载或内存泄漏，加大堆只会让每次停顿更长，根因还在。
- 用 `System.gc()` 想主动回收：只是建议，多数场景反而触发不必要的 Full GC，生产一般加 `-XX:+DisableExplicitGC`。
- 引用队列/ThreadLocal 用完不 remove：线程池复用线程时，ThreadLocalMap 的 key 是弱引用但 value 仍强引用，是常见的隐性泄漏。

### 面试怎么问
「线上 Full GC 频繁怎么排查？」给链路：先确认现象（jstat/GC 日志）→ 看是内存泄漏还是分配速率过高（堆 dump 支配树）→ 查无界集合、缓存、大对象、ThreadLocal → 再决定改代码还是调 GC 参数，最后压测验证。别一上来就说「调大 -Xmx」。

## 动手清单

### 练习 1：亲眼看一次晋升
写个循环不断分配 1MB byte[] 并保留部分引用，加 `-Xmx64m -Xlog:gc*`，观察 Eden 满、Minor GC、对象晋升老年代直到 Full GC 的日志顺序。

### 练习 2：复现一次泄漏
用静态 `List` 持续 add 对象不清理，跑出 `Java heap space`；再改成局部集合，对比 GC 曲线。
**自测标准**：能说清堆/栈/元空间各存什么，能独立读懂一段 GC 日志里的 Eden、Survivor、Old 变化。
